背景信息

UniFi OS 服务器是 Ubiquiti 提供的 UniFi OS 软件版本。UniFi OS 是一款管理平台，负责协调 UniFi 系列应用程序的工作——包括网络管理、安全保护，以及身份识别和更新服务等功能。该服务器由一系列本地主机上的后端服务组成，这些服务通过 Nginx 前端进行连接。Nginx 负责终止 TLS 通信，验证请求内容，并将这些请求转发到相应的内部服务。正是这一代理功能至关重要：整个安全机制依赖于 Nginx 能够准确判断哪些请求是公开的，哪些需要身份验证。

2026 年 5 月 21 日，Ubiquiti 发布了安全公告 064（SAB-064），其中提到了 UniFi 操作系统设备系列存在的五个漏洞。对于未经认证的攻击者来说，最值得关注的三个漏洞分别是：认证网关中的访问控制缺陷和路径遍历漏洞（CVE-2026-34908 和 CVE-2026-34909，这两个漏洞的 CVSS 评分均为 10.0，属于严重级别；攻击向量分别为 CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H 和 package-update ）。此外，还有 package-update 服务中的输入验证缺陷（命令注入漏洞，CVE-2026-34910），该漏洞的 CVSS 评分同样为 10.0，攻击向量与之前的两个漏洞相同。综合这三个漏洞，攻击者就可以实现未经认证的命令执行了。公告指出，访问控制缺陷的幕后主谋是 Duc Anh Nguyen（@heckintosh_），路径遍历漏洞的提出者是 Catchify Security 的 Abdulaziz Almadhi，而命令注入漏洞的提出者则是 John Carroll。

在这篇文章中，我们重点关注未经验证的数据链（CVE-2026-34908、CVE-2026-34909 以及 CVE-2026-34910）。因为攻击者可以在没有认证信息的情况下发起攻击的目标。

受影响UniFi OS硬件&软件版本

UniFi OS Server软件版本≤5.0.6（unifi-core内核5.0.126）存在完整攻击链；5.0.8（内核5.0.153）彻底封堵三条漏洞入口。
各硬件固定受影响基线：

  1. Cloud Gateway/Dream Machine全系列（Pro/SE/Beast）：固件低于5.1.12高危
  2. UniFi Protect NVR/UNVR：固件低于5.1.10高危
  3. UniFi Access门禁主机、Talk语音网关：同5.1.12基线
  4. UniFi Express一体化设备：低于4.0.14高危
  5. UNAS网络存储、交换机控制器模块：同步受内核漏洞影响

UniFi OS底层架构：Nginx+unifi-core分层模型

UniFi OS采用反向代理+微服务分层架构，所有前端请求统一经过Nginx转发，身份校验逻辑独立抽离为unifi-core Node.js服务，内部拆分多业务Go子服务：网络管理、视频录像、门禁、系统包更新。

CVE漏洞概述

CVE ID 凭据要求 类型
CVE-2026-34908 无 授权缺陷（不当访问控制）
CVE-2026-34909 无 路径穿越
CVE-2026-34910 无 命令注入

CVE-2026-34908：认证访问控制判断错误

Nginx 负责处理所有请求，并通过向 unifi-core 节点服务发送子请求来实现身份验证。该服务负责判断一个请求是公开的还是需要身份验证。

/usr/share/unifi-core/app/service.js

此时构造这个特殊的URI：/api/auth/validate-sso/..%2f..%2f..%2fproxy/users/api/v2/ucs/update/latest_package

直接越过校验逻辑，之后Nginx标准化解码后消除../跳转，实际路由指向包更新私有接口/proxy/users/api/v2/ucs/update/latest_package

CVE-2026-34909：路径穿越与 URI 规范化差异

根据之前的URI解析差异绕过鉴权，后端文件读取接口未过滤../、URL编码穿越字符。

处理阶段 看到的值 结果
认证子请求 /api/auth/validate-sso/... 前缀 满足公开 SSO 前缀条件
路由匹配 规范化后的 /proxy/users/api/v2/ucs/update/latest_package 选择 users runnable
业务处理器 /api/v2/ucs/update/latest_package 开始检查 pkg_name

现在来验证一下：

这个错误来自 latest_package 业务处理器，证明了：

  • 认证子请求没有阻断请求；
  • 编码点段被后续路由处理；
  • 请求已经落到 users 更新接口；
  • pkg_name 参数校验开始执行。

CVE-2026-34910：未认证命令注入

users 更新接口接受 pkg_name 和 by_cmd；当 by_cmd=true 且包名存在更新通道时，ULP Go 后端会查询 UOS 的 latest-versions。

/usr/sbin/ulp-go-app

此时给pkgName注入命令就能以ucs-update运行账号自带免密sudo权限，可无密码调用dpkg、systemctl、useradd、chmod等系统工具，注入命令执行后一键切换Root，完整控制操作系统底层。
